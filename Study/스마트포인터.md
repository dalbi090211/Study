# 스마트 포인터
RAII 원칙에 따라 만들고 난 후에 잊어버려도 알아서 해제된다. `<memory>` 헤더에 존재한다.

갑작스럽게 프로그램이 종료되거나 메모리 해제를 잊은 경우 발생하는 메모리 누수를 막기 위해 사용한다.

`unique_ptr<Player> P1 = make_unique<Player>();`와 같은 문법으로 smart, shared, weak 포인터를 생성할 수 있다.
사실상 `Player* P1 = new Player();` 과 동일하게 생성자를 호출한다.

내부적으로는 원시 포인터를 하나 생성하고 소멸자에서 할당된 객체의 소멸자를 호출한다. 이때 `unique_ptr<int[]> players = make_unique<int[]>(10)`과 같은 방식으로 배열을 생성하면 배열을 순회하며 소멸자를 호출한다. `vecotr`나 `list`의 경우 그들의 소멸자를 호출한다. 때문에 자체적으로 구현한 자료형의 경우 그 안의 소멸자를 구현해야 한다.

복사 시에 소멸자가 여러 번 호출되는 문제가 발생할 수 있기에 복제를 구현하지 않았다. 때문에 `move()` 함수를 통해서 소유권을 이전할 수 있다. 이 경우에 원래 소유권을 가지던 포인터는 `nullptr`이 된다. 이때 `move()`는 실질적으로 우측값의 참조(`unique_ptr<int>&&`)만 제공한다. 이후 이동연산자가 호출되고, 원시 포인터의 소유권을 가져온 후 이전한다. 원래 소유권을 가지던 포인터는 `nullptr`이 된다.

# 공유 포인터

공유하는 대상이 1명도 없을 떄 해제한다. 스마트 포인터의 공유가 안되는 문제, 해제 타이밍과 같은 부분을 해결할 수 있다.

다만 서로가 서로를 공유하는 순환 참조 문제가 발생한다.
``` cpp
    shared_ptr<Player> P1 = make_shared<Player>();
    shared_ptr<Enemy> E1 = make_shared<Enemy>();

    P1->SetTarget(E1);  //shared_ptr<Character>로 target에 E1을 등록
    E1->SetTarget(P1);
```
대표적인 상황이 플레이어가 몬스터를 타겟으로 잡고, 몬스터가 플레이어를 타겟으로 잡는 상황이다. 몬스터를 죽이더라도 플레이어가 몬스터의 공유 포인터를 잡고있기에 해제되지 않고, 플레이어가 죽더라도 몬스터의 공유 포인터가 잡고있기에 해제되지 않는 문제가 발생한다.

# 약한 포인터

`shared_ptr` 기반이지만 소유권을 주장하지 않는 포인터. 이를 통해 순환참조 문제를 해결할 수 있음.

`*`와 `->` 연산자를 제공하지 않음. 이는 소유권이 없기 때문에 `weak_ptr`이 참조하는 대상은 언제든지 소멸할 수 있기 때문임. 때문에 접근할 때는 `lock()`을 통해 `shared_ptr`를 반환하고 이를 통해 접근하면 됨.
