# virtual 키워드

`virtual`을 멤버 함수에 붙이면 가상 호출에서 객체의 실제 타입에 맞는 구현을 선택하고, 상속에 붙이면 여러 가상 상속 경로가 하나의 기반 클래스 하위 객체를 공유한다.

# 가상 함수 호출

부모 클래스가 멤버 함수를 `virtual`로 선언하면 자식 클래스에서 그 함수를 오버라이드할 수 있다. `override`는 생략할 수 있다. 명시하면 컴파일러가 실제로 부모의 가상 함수를 오버라이드하는지 검사한다. 예를 들어 아래에서 `Zombie::Speak`의 매개변수를 `int` 하나로 바꾸고 `override`를 그대로 두면 컴파일 오류가 난다.

```cpp
#include <iostream>

class Human {
public:
    virtual void Speak() {
        std::cout << "Hello" << std::endl;
    }
};

class Zombie : public Human {
public:
    void Speak() override {
        std::cout << "grrrrr" << std::endl;
    }
};

int main() {
    Zombie zombie;
    Human& human = zombie;
    human.Speak();  // Zombie::Speak() → grrrrr
}
```

# 다이아몬드 상속

`B`와 `C`가 각각 `A`를 일반 상속하고 `D`가 `B`와 `C`를 상속하면, `D` 객체 안에 `B` 쪽 `A`와 `C` 쪽 `A`가 하나씩 존재한다. 두 경로에서 찾는 함수는 같은 `A::Speak()`다. 하지만 `d.Speak()`를 호출할 때 어느 `A`의 주소를 `this`로 넘겨야 할지 모호해 컴파일 오류가 난다.

`B`와 `C`가 모두 `A`를 가상 상속하면 `D` 안의 두 경로가 같은 `A`에 도달한다. 따라서 아래 예제에서 `d.Speak()`는 공유된 `A`를 대상으로 `A::Speak()`를 호출한다. 여기서 `Speak`는 일반 멤버 함수다.

```cpp
#include <iostream>

class A {
public:
    void Speak() {
        std::cout << "Hello" << std::endl;
    }
};

class B : public virtual A {};
class C : public virtual A {};
class D : public B, public C {};

int main() {
    D d;
    A* viaB = static_cast<B*>(&d);
    A* viaC = static_cast<C*>(&d);
    std::cout << std::boolalpha << (viaB == viaC) << std::endl;  // true
    d.Speak();  // Hello
}
```

# GCC와 MSVC에서의 메모리 배치

객체 안의 테이블 포인터에는 테이블을 참조할 주소 하나가 들어 있다. 가상 기반 객체를 찾을 때는 테이블에서 바이트 오프셋을 읽고, 가상 함수를 호출할 때는 해당 슬롯에서 호출할 코드의 주소를 읽는다. 함수 본문은 실행 파일의 코드 영역에 있다.

GCC에서 `vptr`는 가상 테이블의 기준 위치를 가리킨다. 이 테이블은 가상 기반 클래스까지의 오프셋을 담을 수 있고, 가상 함수가 있으면 호출할 코드의 주소도 별도 항목에 담는다.
MSVC에서 `vbptr`는 가상 기반 클래스까지의 오프셋을 담은 `vbtable`을 가리킨다. 가상 함수 호출에 쓰는 `vfptr`는 호출할 코드의 주소를 담은 `vftable`을 가리킨다.
