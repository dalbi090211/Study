# virtual 키워드

동일한 이름의 구현에 대해 하나의 실체만 존재할 수 있게 한다. 객체의 경우 `A`를 상속한 `B, C`가 존재하고, `B, C`를 상속한 `D`가 존재한다고 했을 때 보통의 경우 `D`에는 `A`가 2개 존재하게 된다. 이때 `A`에 일반 함수가 존재하고, 이를 `D`를 통해 접근하게 된다면 어떤 함수에 대해 접근해야 할지 몰라 모호하다며 컴파일 할 수 없는 문제가 발생한다. 이때 `B, C`가 `A`를 상속할 때 `virtual` 키워드를 붙여주게 된다면 해결할 수 있다.

이는 `virtual` 키워드가 여러 상속 경로가 존재할 때 하나만 두고 공유하도록 만들기 때문이다. 상속받은 클래스 `D`에는 `B, C`가 공유하는 객체 `A`만 만들어진다. 더 이상 `B, C`는 자신 안에 `A`를 생성하는 게 아닌 `vbptr`을 통해 `vbtable`에 자신과 `A`가 얼마나 떨어져 있는지 적혀있는 위치에 접근하고, 이를 통해 `A`에 접근하게 된다.

이때 `D`의 생성자에서 먼저 `B`의 가상 함수를 호출하는 순간 `B`에서의 `this`의 위치가 애매해지는데 이런 상황에서 `A`와의 위치를 보정하기 위해 `vtordisp`라는 멤버 변수를 생성하여 사용한다.


`virtual` 키워드가 붙은 함수에 대하여 자신의 구현이 있다면 자신의 함수에 대한 함수 포인터를, 없으면 부모의 함수 포인터를 가상테이블에 저장함. 함수는 코드 영역에 되고, 함수 포인터의 위치는 컴파일러에 의해 객체 내에 다른 변수들과 같이 배치되어지기에 확인하기 힘듬.

# vbptr, vfptr

``` cpp
class Human {
public :
    virtual void Speak(){
        cout << "Hello" << endl;
    }
};


class Zombie : virtual Human {
    void Speak() override {
        cout << "grrrrr" << endl;
    }
};
```

`virtual` 키워드로 상속받게 되면 객체의 경우는 `vbptr`(virtual base pointer), 함수의 경우에는 `vfptr`(virtual function pointer)이 생성된다. 그리고 `vbptr`은 `vbtable`에 저장된 상속 객체 까지의 바이트 오프셋의 주소를 가지고, `vfptr`은 `vftable`에 저장된 함수 코드의 주소를 가진다.

상속한 함수는 `override` 키워드를 붙여 내부의 구현을 다르게 가져갈 수 있고, `Human::Speak()`와 같이 부모의 구현을 호출할 수도 있다.
