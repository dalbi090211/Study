# 포인터

포인터는 타입의 주소를 저장하는 자료형이다. 선언 시 지정된 타입에 맞게 주소를 해석하고, 이동한다.

예를 들어 `int* Pointer` 이라고 선언한다면 `Pointer++` 시 현재 환경에서 int형의 크기인 4바이트만큼 주소를 이동한다. 또 `*Pointer`로 데이터 접근 시 4바이트만큼의 메모리를 읽고 이를 int형으로 해석한다. 포인터의 크기는 빌드 대상에 따라 다르며, 일반적으로 32비트 프로그램에서는 4바이트, 64비트 프로그램에서는 8바이트이다. 현재 환경에서 `int* Pointer = new int`의 포인터 자체 크기는 8바이트이고, 별도로 할당한 int가 4바이트이다. 둘의 데이터 크기를 합치면 12바이트이지만 포인터 자체가 12바이트인 것은 아니다.

주소는 보통 0x로 시작하는 16진수로 표현한다. 32비트 주소는 최대 8자리, 64비트 주소는 최대 16자리이며 앞쪽의 0은 생략될 수 있다.

현대 Cpp에서는 RAII 원칙에 따라 이 방식보다는 smart pointer를 통한 관리를 사용한다. RAII 원칙이란 자원의 획득을 객체의 초기화에, 자원의 해제를 객체의 소멸에 연결한다는 원칙으로 자원의 관리를 프로그래머의 직접적인 선언과 해제에 의존하기 보다는 애초에 안정성을 가진 자료형을 사용하자는 취지인거 같다. 가비지 컬렉션과 다른 점은 해제 타이밍만 안정장치를 구현에 의한 안전장치를 두고, 할당과 변경은 여전히 코드에 의존함으로써 자원 관리의 효율성?을 유지한다는 취지인 것 같은데 솔직히 잘 모르겠다.

아무튼 `int* Pointer = new int[4]`로 선언 시에 일어나는 일은 다음과 같다.

1. int 값 4개를 저장할 공간을 힙 메모리에 동적 할당한다.
2. 이들의 첫번째 주소를 가리키는 int 포인터 Pointer를 스택 메모리에 생성한다.

이때 할당되는 메모리는 힙 메모리에 생성되기에 반드시 `delete[] Pointer`와 같은 해제를 사용해주어야 한다. 

그 전에 힙 메모리와 스택 메모리의 차이에 대해 짚고 넘어갈 필요가 있다. 힙 메모리란 동적 할당되는 변수가 존재하는 메모리로 프로세스 전체가 공유한다. 반면에 스택 메모리는 함수의 일반 지역 변수(자동 변수) 등이 존재하는 메모리로 스레드 단위로 사용한다. static 변수는 스택에 저장되지 않는다. 스택 크기는 환경과 설정에 따라 다르며, 일반적으로 힙에서 사용할 수 있는 공간보다 작다.

프로세스의 자원을 각 스레드들이 같이 사용하기에 크기 자체는 힙 메모리가 더 크지만, 한정된 자원을 같이 사용하기에 필요한 경우가 아니라면 스택에 할당하는 편이 좋다. 힙에 할당하는 것은 스택에 비해 훨씬 비싼 연산이며, 스택은 힙보다 가볍고 빠르며, 자동으로 해제가 되기에 메모리 누수가 일어나지 않는다.

자료형 뒤에 붙는 포인터는 그 자료형의 포인터를 뜻한다. 자료형의 크기에 따라 연산 시 주소의 위치를 이동한다. `char*`형이라면 1바이트만큼, `double*`은 8바이트를 단위로 이동, 해석한다. 이떄 `void*` 형을 사용할 수도 있는데 이는 주소만 저장할 뿐 이동이나 해석은 불가능하다.

# vector와 linked list의 차이

둘 다 동적할당이지만 벡터는 인덱스를 통한 조회가 O(1)이고, linked list는 삽입, 삭제할 위치를 이미 알고 있다면 해당 연산이 O(1)이다. linked list에서 위치를 찾는 과정은 O(n)이 걸릴 수 있다.

vector는 기본적으로 지정된 사이즈만큼 힙 메모리를 할당한 후 인덱스에 따라 값을 넣는다. 초기 값을 넣을 수도 안넣을 수도 있다. 이후 할당된 크기를 넘으면 지정된 배율만큼 키운 크기로 재할당을 시도한다. 재할당 시 새공간 확보와 별개로 본인 데이터의 이관을 위한 O(n)의 시간 복잡도를 필요로 한다.

linked list는 그때그떄 할당하고 연결한다. 따라서 파편화된 데이터 구조를 가진다.

따라서 인덱스로 조회할 때는 vector가 적합하고, 위치를 이미 알고 있는 중간 삽입, 삭제가 잦다면 linked list가 유리할 수 있다. 크기가 자주 변한다는 이유만으로 linked list가 더 적합한 것은 아니며, vector의 끝에 추가하는 연산은 분할 상환 O(1)이다.

# 유니크 포인터

기존의 포인터는 자원의 관리 책임이 프로그래머에게 있어, 메모리 누수가 발생할 수 있는 가능성이 존재했음. RAII 원칙에 따라 이를 방지하기 위해 해제를 자동으로 하는 유니크 포인터를 만듬. `unique_ptr<int> ptr = make_unique<int>()`과 같은 방식으로 생성할 수 있음. 내부 구현은 단순히 원시 포인터를 두고, 해제 시에 참조하던 메모리를 삭제하는 방식임. 따라서 복사 생성자와 복사 대입 연산자가 삭제되어있음. 때문에 이동을 위해서라면 move() 함수를 사용해야 함. std::move 자체는 이동 가능한 형태의 참조로 변환할 뿐이고, 실제 소유권 이전과 원래 포인터의 nullptr 처리는 unique_ptr의 이동 생성자나 이동 대입 연산자가 수행함.
